# 完成定义

完成定义用于判断任务或阶段是否真的结束。代码写完不等于完成；必须有
与任务规模匹配的验证证据。

## 1. 通用完成条件

所有任务都必须满足：

- 实现范围与准入目标一致，没有悄悄扩大范围；
- 代码和注释简洁、完整，非显然逻辑有必要的意图说明；
- 相关检查已经运行并记录结果；
- 没有已知且未说明的失败、回归或风险；
- 任务状态、变更文件、验证证据和下一步已更新；
- 达到适中节点时，按规则创建节点提交并推送到 `origin`。

## 2. 小改动

适用范围：一个对话框、一个下拉框、局部文案或不改变架构/数据结构/用户
流程的小范围修正。

最低要求：

- 相关 TypeScript/Python 类型检查通过；
- 有逻辑时补充或更新聚焦单元测试；
- 直接检查改动没有引入明显语法或导入错误；
- 在任务日志中记录验证结果。

小改动不必单独构成 Git 节点。可以与同一验收目标下的其他小改动合并，
在适中节点完成后统一提交。

## 3. 完整页面或大模块

适用范围：一个完整页面、跨多个组件的用户流程、Python/Electron 契约、
知识检索切片或其他具有独立用户/工程价值的模块。

最低要求：

- 单元测试覆盖主要逻辑和关键失败路径；
- 类型检查通过；
- 生产构建通过；
- 真实运行并完成直接交互验证；
- 结果、限制和风险写入任务状态与日志；
- 形成一个适中、可独立审查的 Git 节点。

## 4. 阶段完成

阶段完成必须同时满足：

- 阶段目标中的功能范围全部完成；
- 适用的单元测试、类型检查、生产构建和交互验证全部通过；
- 阶段验收记录完整，包含实际证据和未解决风险；
- 已创建并推送阶段节点提交；
- Agent 停止继续推进，等待用户亲自手动验证；
- 用户明确回复批准该阶段。

自动化检查通过只能表示“准备人工验收”，不能自动视为阶段完成。

## 5. 不算完成的情况

- 只有代码，没有可复现的验证证据；
- 只通过单元测试，但页面或交互未实际检查；
- 构建通过，但用户流程与目标不一致；
- 把未完成的多个功能混在一个无法审查的大节点中；
- 已知失败被隐藏在日志、状态或提交信息之外；
- 未经用户批准就从当前阶段进入下一阶段。

## 6. 验收记录

使用 `harness/templates/acceptance.md` 记录具体任务。阶段验收还必须包含
用户手动验证和明确批准的记录。
