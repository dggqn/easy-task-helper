# 任务准入标准

本文件规定一个开发任务何时可以开始。它约束当前项目的开发 Agent，
不是未来产品运行时的 Agent 规则。

## 1. 必备信息

开始实现前，任务必须能够回答以下问题：

- **目标**：要解决什么问题，给用户带来什么结果？
- **范围**：本次包含哪些内容，明确不包含哪些内容？
- **验收条件**：怎样判断任务完成，必须观察到什么结果？
- **影响面**：会影响 Electron、React/TypeScript、Python、知识库、模型
  适配层、CI/CD 中的哪些部分？
- **验证方式**：需要哪些类型检查、单元测试、构建检查和实际交互验证？

如果这些信息不足以形成可执行的验收目标，任务不得直接进入实现阶段，
应先停下并向用户说明缺口。

## 2. 当前项目默认上下文

除非用户明确修改，任务可以复用以下已确认上下文：

- 产品是 Electron 桌面端 + Python AI 开发编排 + 向量知识库 + 示例代码。
- 首个支持类型是前端 Web 页面项目。
- 首期产品壳使用 Electron + React + TypeScript；Python 使用 3.12，包管理
  使用 `uv`。
- `agnes` 是预留模型提供方，但接口地址、鉴权、模型名和协议尚未确定。
- 当前工作目录内允许安装依赖、修改配置、运行测试和开发服务；不得删除
  项目根目录。
- UI 默认中文优先、深色工业科技风、简洁明了、偏聊天型，并适配常用桌面
  缩放。

## 3. Phase 1 默认准入目标

Phase 1 的任务必须服务于以下目标：

让用户可以从占位数据中选择一个前端 Web 项目，进入任务对话页面，并看见
所选项目和占位任务进度。真实模型调用、向量库、真实项目改写和线上发布
不属于这一阶段。

## 4. 准入检查清单

- [ ] 目标可以用一句话说明。
- [ ] 范围和排除项已写明。
- [ ] 有至少一个可观察的验收结果。
- [ ] 已判断任务是小改动、完整页面/模块，还是阶段节点。
- [ ] 已列出适用的测试、类型检查、构建和交互检查。
- [ ] 没有未经说明的架构、依赖、数据结构或用户流程变化。
- [ ] 任务状态已写入 `harness/state/task-state.json` 或对应验收记录。

## 5. 必须停下的情况

以下情况不能靠猜测继续：

- 需求会改变架构、依赖、持久化数据结构或用户流程；
- 需要确认 `agnes` 的接口、凭据或数据发送范围；
- 验收条件互相矛盾或无法观察；
- 任务要求超出当前工作目录权限；
- 任务涉及发布、部署、删除根目录或其他未定义的外部影响。

停下时应给出：已知事实、缺失信息、可选方案、推荐方案及其影响。
